# Six candidate layouts

All candidates retain the same preset and product content. Fonts and colors are constraints; the exploration varies the workspace structure.

## A — Split workbench (selected for full draft)

Designer lens: Dieter Rams's hierarchy and functional grouping, interpreted for a tool rather than imitating a physical product. Persistent left library, editor in the center, result inspector on the right; compact neutral surfaces and fine dividing rules. The hero material is a probability distribution paired with an annotated source image. The distinctive move is keeping questions and their answers adjacent. Form follows the repeated edit/run/inspect loop.

## B — Focused notebook (selected for full draft)

Reference lens: Open WebUI's workspace and history, verified at https://openwebui.com/blog/v0-11-0-the-interface-reorganized. Source screenshots: `references/openwebui*.png`. Borrow the persistent library, restrained text hierarchy, and focused main column; use a structured notebook instead of conversation bubbles. State and question blocks flow vertically with a compact pinned result summary. The hero material is the input photograph inside the state block. Form follows the user's familiar workspace reference without treating decisions as chat.

## C — Visual inspector (selected for full draft)

Designer lens: Bret Victor's principle of keeping an artifact and its controls visibly connected. A slim top navigation, compact question rail, large image canvas and a results dock create a distinct inspection workspace. Dark neutral preset surfaces support the photo, with pink used for the selected region and controls. The hero material is the Box overlay; one image-centered composition carries the visual emphasis. Form follows the requirement to locate model decisions in the source image.

## D — Request console (alternate)

Reference lens: https://hoppscotch.io, screenshot `references/hoppscotch.png`, visually inspected. Borrow its narrow tool rail, top request action row, tabbed parameters and horizontal results dock. Model/connection selectors replace the HTTP address row. Hero material: structured JSON and a compact result table. Form follows API request/response inspection; this is a more developer-oriented alternative.

## E — Decision matrix (alternate)

Roulette: sampled second 21; web index `21 % 20 + 1 = 2`, Neo-Brutalism. Viewed `web/02-neo-brutalism.jpg` in the installed skill specimens. Adapt its hard-edged modular grid and single emphatic color block to the requested neutral/pink palette; omit its multiple clashing colors and decorative display typography. Four question/result modules surround a narrow shared state strip. Hero material: four different typed result visualizations. This is the boldest candidate, intentionally less quiet than the tools above.

## F — Image folio (alternate)

Roulette: sampled second 21; east index `21 % 12 + 1 = 10`, Hattori Playful Offset. Viewed `east/10-hattori-playful-offset.jpg`. Borrow one displaced rectangular image/result relationship while keeping controls rigorously aligned. Use a large left photograph, right question form, and a small offset pink probability panel. No striped typography or decorative gestures; the palette and Inter remain fixed. Hero material: the annotated image. This selective adaptation preserves about half the source style, prioritizing application usability.

## Selection rationale

A supports daily repeated testing, B makes the workflow approachable, and C gives image decisions the most space. They differ in hierarchy and spatial organization. D repeats A's developer-tool emphasis; E sacrifices calm for emphasis; F provides less room for multi-question editing. All six remain visible in `thumbs.html`.
